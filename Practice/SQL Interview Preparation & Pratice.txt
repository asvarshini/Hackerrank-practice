# SQL Interview Preparation & Practice

## Q1 — SELECT + WHERE

**Question:**
Display the names and salaries of employees who earn more than 50,000.

**My Answer:**

```sql
SELECT name, salary
FROM Employees
WHERE salary > 50000;
```

**Result:** Correct ✅

**Concept:** `SELECT` chooses columns, `WHERE` filters rows.

## Q10 — GROUP BY

**Question:**

**My Answer:**


## Q11 — HAVING

**Question:**
Find departments whose average salary is greater than 50,000.

**My Answer:**

```sql
SELECT AVG(salary) AS sal, department
FROM Employees
GROUP BY department
HAVING sal > 50000;
```

**Result:** Correct in MySQL ✅

More portable version:

```sql
SELECT department, AVG(salary) AS average_salary
FROM Employees
GROUP BY department
HAVING AVG(salary) > 50000;
```

**Important difference:**

```sql
WHERE
```

→ filters rows before grouping.

```sql
HAVING
```

→ filters groups after `GROUP BY`.

## Q15 — INNER JOIN vs LEFT JOIN

**Question:**
What is the difference between INNER JOIN and LEFT JOIN?

**My Answer:**

> INNER JOIN gives similar values present in both tables and LEFT JOIN gives all rows present on the left table and matching rows on the right table.

**Result:** Correct concept ✅

Better interview explanation:

> INNER JOIN returns only rows where there is a match in both tables. LEFT JOIN returns all rows from the left table and matching rows from the right table. If there is no match, the right-side columns contain NULL.

## Q16 — Subquery

**Question:**
Find employees whose salary is greater than the average salary of all employees.

**My Answer:**

```sql
SELECT employee_id
FROM (
    SELECT AVG(salary) AS sa
    FROM Employees
)
HAVING salary > sa;
```

**Result:** Incorrect ⚠️

Correct approach:

```sql
SELECT employee_id, name, salary
FROM Employees
WHERE salary > (
    SELECT AVG(salary)
    FROM Employees
);
```

**Concept:**

The subquery calculates the overall average first. The outer query compares every employee's salary with that average.

## Q17 — CASE WHEN

**Question:**
Classify employees based on salary:

* Salary >= 55,000 → High
* Salary 40,000–54,999 → Medium
* Salary < 40,000 → Low

**My Answer:**

```sql
SELECT
    CASE
        WHEN salary >= 55000 THEN 'High'
        WHEN salary >= 40000 AND salary <= 54999 THEN 'Medium'
        ELSE 'Low'
    END
FROM Employees;
```

**Result:** Correct ✅

Better version:

```sql
SELECT
    name,
    salary,
    CASE
        WHEN salary >= 55000 THEN 'High'
        WHEN salary >= 40000 THEN 'Medium'
        ELSE 'Low'
    END AS salary_category
FROM Employees;
```

**Concept:** `CASE WHEN` is SQL's conditional `IF/ELSE` logic.

## Q21 — WHERE vs HAVING

**Question:**


**My Answer:**

```sql

FROM Employees
GROUP BY department
```

**Concept:**

`WHERE` is for filtering individual rows.

`HAVING` is for filtering grouped/aggregated results.

## Q24 — Monthly Revenue

Find total revenue for each month.

**My Answer:**

```sql

```

**Result:** Partially correct ⚠️

The problem is grouping by the individual date instead of the month.



## Q25 — Running Total

**Question:**
Calculate a running total of revenue month by month.

**Result:** I did not know this one initially.

Correct pattern:

```sql
SELECT
    month,
    monthly_revenue,
    SUM(monthly_revenue) OVER (
        ORDER BY month
    ) AS running_revenue
FROM (
    SELECT
        DATE_FORMAT(order_date, '%Y-%m') AS month,
        SUM(amount) AS monthly_revenue
    FROM Orders
    GROUP BY DATE_FORMAT(order_date, '%Y-%m')
) AS monthly_data
ORDER BY month;
```

**Concept:**

```sql
SUM(monthly_revenue) OVER (ORDER BY month)
```

creates a cumulative/running total.

## Q28 — Customer Total Spending

**Question:**
Show customer name and total amount spent, including customers with no orders.

**My Answer:**

```sql
SELECT c.name,
       SUM(amount) AS s
FROM Customers c
LEFT JOIN Orders o
ON o.customer_id = c.customer_id
GROUP BY customer_id;
```

**Result:** Mostly correct ⚠️

Better version:

```sql
SELECT
    c.customer_id,
    c.name,
    COALESCE(SUM(o.amount), 0) AS total_spent
FROM Customers c
LEFT JOIN Orders o
    ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.name;
```

**Important concepts:**

* `LEFT JOIN` keeps customers without orders.
* `SUM()` calculates total spending.
* `COALESCE()` converts NULL to 0.

## Q29 — CTE

**Question:**
What is a CTE?

**My Answer:**

> CTE is like creating a fake table first and then writing a query for the answer we want.

**Result:** Basic understanding is correct ✅

Better interview explanation:

> A CTE, or Common Table Expression, is a temporary named result set created using the `WITH` clause. It can be used by the main query and exists only for the duration of that query.

Example:

```sql
WITH customer_totals AS (
    SELECT
        customer_id,
        SUM(amount) AS total_spent
    FROM Orders
    GROUP BY customer_id
)
SELECT *
FROM customer_totals
WHERE total_spent > 1000;
```

**Result:** Concept correct, but initially had syntax errors.

## Q34 — ROW_NUMBER()

**Question:**
Find the highest-paid employee in each department, but if two employees have the same highest salary, return only one employee.

**My Answer:**

```sql
WITH du AS (
    SELECT
        name,
        employee_id,
        salary,
        ROW_NUMBER() OVER (
            PARTITION BY department
            ORDER BY salary DESC
        ) AS rank
    FROM Employees
)
SELECT name, employee_id, salary
FROM du
WHERE rank = 1;
```

**Result:** Concept correct; initially missed a comma after `salary`.

Correct version:

```sql
WITH du AS (
    SELECT
        name,
        employee_id,
        salary,
        ROW_NUMBER() OVER (
            PARTITION BY department
            ORDER BY salary DESC
        ) AS rn
    FROM Employees
)
SELECT
    name,
    employee_id,
    salary
FROM du
WHERE rn = 1;
```

**Key difference:**

`ROW_NUMBER()` gives every row a unique number, even when values are tied.

## Q35 — JOIN Duplication Trap

**Question:**
Find total order amount for each customer without accidentally double-counting orders because of duplicate payment records.

**My Answer:**

```sql
SELECT DISTINCT
    c.customer_id,
    SUM(o.amount) AS tot
FROM Customers c
JOIN Orders o
    ON c.customer_id = o.customer_id
GROUP BY o.customer_id;
```

**Result:** Correct approach ✅

The important point was to calculate from `Orders.amount` without joining `Payments`, because duplicate payment rows could multiply the order rows.

Cleaner version:

```sql
SELECT
    c.customer_id,
    SUM(o.amount) AS total_amount
FROM Customers c
JOIN Orders o
    ON c.customer_id = o.customer_id
GROUP BY c.customer_id;
```

## Q36/Q37 — Above Department Average

**Question:**
Find employees whose salary is greater than the average salary of their own department.

**My First Attempt:**

```sql
WITH new AS (
    SELECT
        employee_id,
        name,
        department,
        AVG(salary) AS avg_sal
    FROM Employees
    GROUP BY department
)
SELECT employee_id, name, department, salary
FROM new
WHERE salary > avg_sal;
```

**Result:** Incorrect ⚠️

The problem is that `GROUP BY department` creates one row per department, so individual employee salary information is lost.

Correct approach:

```sql
SELECT
    employee_id,
    name,
    department,
    salary
FROM (
    SELECT
        employee_id,
        name,
        department,
        salary,
        AVG(salary) OVER (
            PARTITION BY department
        ) AS department_avg
    FROM Employees
) AS e
WHERE salary > department_avg;
```

**Key concept:**

```sql
AVG(salary)
GROUP BY department
```

→ one row per department.

But:

```sql
AVG(salary) OVER (PARTITION BY department)
```

→ keeps every employee row and adds the department average.

## Q38 — UNION vs UNION ALL

**Question:**
What is the difference between UNION and UNION ALL?

**My Answer:**

> UNION gives the result of the two tables which does not contain NULL. UNION ALL gives the table regardless of NULL.

**Result:** Partially correct ⚠️

Correct explanation:

> `UNION` combines results and removes duplicate rows, while `UNION ALL` combines results and keeps duplicates. Both can contain NULL values.

Example:

Table A:

```text
1
2
3
```

Table B:

```text
3
4
5
```

`UNION`:

```text
1
2
3
4
5
```

`UNION ALL`:

```text
1
2
3
3
4
5
```

## Q40 — Second Highest Salary Per Department

**Question:**
Find the second-highest salary in each department, considering distinct salary levels.

**My Answer:**

```sql
SELECT
    name,
    salary,
    DENSE_RANK() OVER (
        PARTITION BY department
        ORDER BY salary DESC
    ) AS ra
FROM Employees
WHERE ra = 2;
```

**Result:** Concept correct, but the query has syntax/processing issues.

Correct approach:

```sql
WITH ranked AS (
    SELECT
        department,
        name,
        salary,
        DENSE_RANK() OVER (
            PARTITION BY department
            ORDER BY salary DESC
        ) AS salary_rank
    FROM Employees
)
SELECT
    department,
    salary AS second_highest_salary
FROM ranked
WHERE salary_rank = 2;
```

**Why DENSE_RANK?**

If salaries are:

```text
60000
60000
50000
```

then:

```text
60000 → rank 1
60000 → rank 1
50000 → rank 2
```

Therefore 50,000 is the second-highest **distinct** salary.
